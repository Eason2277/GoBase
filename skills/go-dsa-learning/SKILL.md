# Go 数据结构与算法学习

## 学习目标

帮助学习者从前端工程经验出发，理解数据结构和算法的运行机制，并能用 Go 建模、实现、测试和解释真实业务问题。书中的 Java 示例只作为思想来源，不作为 Go 代码模板。

## 固定教学流程

每个知识点都按以下顺序推进：

1. 先提出一个小而真实的业务问题，例如购物车、订单、库存、搜索、撤销操作或服务依赖。
2. 明确参与者、输入、状态变化、输出，以及当前步骤在完整业务流程中的边界。
3. 从业务需求推导抽象数据类型（ADT）：数据、允许的操作、不变量。
4. 先让学习者预测行为或选择数据结构，再给出最小必要解释。
5. 让学习者一次只完成一个可运行的 Go 代码步骤；除非明确要求代写，不直接给出完整最终实现。
6. 运行或测试后，解释执行过程、内存关系、时间复杂度和空间复杂度。
7. 对比 Go 内置类型或标准库的工程用法，说明手写实现的学习价值和生产边界。
8. 给出一道不同业务场景的迁移练习，不提供完整答案；先检查建模，再检查代码。

每次课程至少说明：目标、操作、为什么、预期结果、验证方式和当前边界。

## 推荐路线

按照前置依赖推进：

1. 数组、切片、结构体、指针、顺序表和复杂度。
2. 链表、栈、队列，以及它们在撤销、任务处理和消息消费中的应用。
3. 选择排序、插入排序、归并排序、快速排序、堆和优先队列。
4. 顺序查找、二分查找、符号表、哈希表和二叉查找树。
5. 图的邻接表、DFS、BFS、连通分量、拓扑排序和最短路径。
6. 字符串查找和 Trie；只有出现搜索、自动补全或知识库检索需求时深入高级实现。

优先覆盖《算法（第 4 版）》第 1 章至第 4 章的核心思想；不要求一开始读完整本书或完整实现所有高级算法。

## Go 实现边界

- 先使用数组、slice、struct、指针和普通函数理解底层模型，再使用 `map`、`container/heap` 等标准能力。
- 解释 slice 是描述底层数组的窗口，`len`、`cap`、`append` 和共享底层数组必须通过小实验验证。
- 不把 `map` 的会用等同于掌握哈希表；需要说明哈希、冲突、扩容和平均复杂度的边界。
- 不把排序库调用等同于理解排序；至少手写一个基础排序，并用标准库作为对照。
- 讲指针、链表、树和图时，优先展示节点或邻接关系的状态变化，而不是只给抽象定义。
- Go 示例保持独立、可运行，优先使用标准库，不为了学习数据结构引入框架或第三方依赖。

## 前端经验的桥接方式

可以使用 JavaScript/TypeScript 做入口类比，但必须指出差异：

- JS 数组和 Go slice 都支持索引，但内存布局、类型约束和扩容语义不同。
- TypeScript `Map` 和 Go `map` 都是键值结构，但不能据此跳过哈希表的冲突与复杂度。
- React/Vue 状态列表解决的是 UI 状态管理问题，不等于服务端并发环境下的数据结构安全。
- 前端队列、请求缓存和撤销栈可以作为场景，但算法和数据结构仍按 Go 的真实执行模型解释。

## AI 协作规则

把 AI 当作讲解者、反例生成器、代码审查者和测试设计者，不把生成代码当作学习结果。每次回答应优先帮助学习者判断：

- 这个业务问题需要哪些操作和不变量？
- 为什么选择当前数据结构，而不是另一个结构？
- 最坏、平均和最好情况下的成本分别是什么？
- 哪些结论是语言保证，哪些只是实现或业务假设？
- 什么测试或实验能验证结论？

当学习者第一次接触概念时，保持交互式节奏：一个问题、一个代码步骤、一次验证。只有用户明确要求快速参考或直接实现时，才提供完整代码。

## 课程完成信号

当学习者能够从一个新业务需求选择数据结构、说明关键操作和复杂度、写出最小实现、设计边界测试，并解释为什么生产代码可能使用标准库时，才进入下一种核心数据结构。
